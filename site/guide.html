Feature guide

Everything in Forge ML

A desktop scientific IDE for Rust machine-learning projects. Open a Cargo project, edit Rust scripts or //# %% notebooks, run cells in a persistent Evcxr console, and arrange the whole workspace to fit how you work. This guide covers every pane and feature.

Install & run

Download v1.4.0 — native installers with the offline Rust runtime bundled in:

  • Windows (10/11, x64): Installer (.exe) · portable forge_ide.exe
  • macOS (Apple Silicon): Disk image (.dmg)
  • Linux (x86_64): AppImage · .deb

Verify against SHA256SUMS, or grab any build from all releases.

Prefer to build from source? Forge ML is a Cargo workspace. On Windows, use a Visual Studio Native Tools command prompt so Cargo can find the MSVC linker:

cargo run

Release installers bundle the correct rust-analyzer for each platform. Development builds can install or repair it from the Help pane, or manually:

rustup component add rust-analyzer
Tagged releases build an NSIS installer for Windows, a DMG for macOS, and DEB/AppImage packages for Linux, each with the matching rust-analyzer sidecar and a build-provenance attestation. Forge can report an available update, but installing it is always an explicit action.

The dockable workspace

The layout follows the scientific-IDE model — an editor in the center surrounded by tool panes — but every surface is a dockable pane you can rearrange freely.

Dock & split
Drag a pane's tab onto another region to move it, or onto an edge to split. Drop it on an existing tab bar to group panes together as tabs.
Reorder & resize
Drag tabs within a group to reorder them; drag the splitters between regions to resize. Editor tabs also reorder by dragging, and close on middle-click.
Show / hide
Open View → Panes to toggle any pane on or off. View → Reset layout to default restores the standard arrangement at any time.
Remembered
Your arrangement — splits, groupings, sizes, hidden panes, and each pane's scroll position — is saved and restored across restarts. If a saved layout can't be read (for example after an upgrade that changes the pane set), Forge falls back to the default.

The default layout places a Files / Outline group over the notebook Cells rail on the left, the editor in the center over a Console / History / Python / Data viewer group at the bottom, and all inspector panes as a tab group on the right.

Terminals & Rust kernels

Two families of interactive panes let you work without leaving the IDE, and you can open as many of each as you like.

Embedded terminals
A real system terminal running your shell (ConPTY on Windows, a pty on Linux/macOS), so vim, htop, and full-screen apps work. It supports truecolor, scrollback, drag-select with copy, and resizes with the pane. Open more with View → New terminal or by right-clicking a terminal tab.
Rust kernels
Independent Rust REPLs, each backed by its own Evcxr session with isolated state. Type an expression and press Enter; use the pane's clear / restart / stop controls. Open more with View → New Rust kernel or from a kernel tab. These are separate from the notebook-linked Console pane.
Every terminal and kernel is a first-class dock pane: tab them together, split, drag anywhere, float into a window, hide, or reorder — each independently. Close one with the × on its tab to end that session.

Notebook cells

Separate cells with a //# %% <name> marker. Cells share one Evcxr session, so setup and dataset cells define values that later cells and console commands reuse.

//# %% setup
let learning_rate = 0.05_f64;
let epochs = 8_usize;

//# %% data
let features = vec![1.0_f64, 2.0, 3.0, 4.0, 5.0];
let targets  = vec![2.2_f64, 4.1, 6.0, 8.2, 10.1];

//# %% train
let mut weight = 0.0_f64;
for _ in 0..epochs {
    let g = features.iter().zip(&targets)
        .map(|(x, y)| (weight * x - y) * x).sum::<f64>() / features.len() as f64;
    weight -= learning_rate * g;
}
println!("Learned weight: {weight:.4}");

The Cells pane shows each cell with a status marker — queued, running, passed, or failed — and controls to insert, move, delete, and clear outputs. Run one cell (Shift + Enter), everything above the selection, all cells, or restart-and-run-all. A long run can be stopped safely.

Telemetry markers

Publish visualizations from any cell by printing structured lines to stdout:

println!("forge_metric:loss={}", loss);            // live line chart
println!("forge_vector:weights=0.2,0.7,1.1,1.8");  // bar plot
println!(r#"forge_table:samples={"columns":["x","label"],"rows":[[0.2,"cat"]]}"#);
println!(r#"forge_plot:{"name":"roc","kind":"line","series":[...]}"#); // structured plot

Metrics appear in Plots, vectors and tables in Data. Structured forge_plot: JSON supports 11 families — lines, scatter, bars, areas, 24-bin histograms, five-number box summaries, heatmaps, ROC, precision–recall, residuals, and feature importance — each with per-series toggles, log axes, and SVG / PNG / PDF / interactive-HTML export.

Training and deployment panes ingest framework-neutral forge_training:, forge_service:, and forge_drift: events, and concurrent producers can scope them with forge_training[run-id]:.

Editor & rust-analyzer

The editor supports multiple tabs with independent unsaved-change protection. It synchronizes documents with rust-analyzer for inline diagnostic underlines, hover messages, a caret-anchored completion popup, and Ctrl+click go-to-definition — including definitions in other files. Find and replace works in the active file (Ctrl + F); project-wide search (Ctrl + Shift + F) returns clickable results.

The Debug menu offers working analysis and inspection actions — run code analysis, open Problems, inspect variables, and restart the Rust console. Step debugging is not available yet.

Data & the grid

Import CSV, TSV, JSON Lines, Parquet, or Arrow IPC from the Data pane or the Tools menu. Parsing runs in the background and opens the result in the data viewer only after Arrow construction and quality profiling finish. Interactive imports are bounded (512 MiB on disk, one million rows, 10,000 columns); query or stream larger sources. Tools → Import via Millwright loads CSV and Parquet through the embedded Millwright 2.2.1 crate.

Each dataset gets a cached quality profile — missingness, numeric coverage, uniqueness, range, mean, standard deviation, mixed-type and constant-column alerts, and bounded Pearson correlations. The grid is virtualized, so wide tables stay responsive while you filter, sort, pin or hide columns, edit drafts, export a selection, and build linked scatter plots. Filtering and sorting run on a coalescing background worker with revision-safe result delivery.

Full-table exports to CSV, TSV, JSON Lines, Parquet, and Arrow IPC stream on the background worker, writing a sibling temporary file and replacing the destination only after success.

Experiments

New runs carry SHA-256 fingerprints for dataset contents, hashed source identities, the Cargo lockfile, and selected runtime metadata. Name, snapshot, compare, clone, and archive runs; overlay metrics across runs; and export ZIP bundles containing the run manifest and referenced artifacts. Historical runs remain readable and are labeled when they use legacy fingerprints. Produce EDA and experiment-comparison reports as self-contained offline HTML or native PDF.

File → Export reproducible project bundle creates a deterministic ZIP with a schema-2 manifest, file sizes, and SHA-256 digests, excluding build directories, virtual environments, Forge / Git state, and credential-like files.

Plots

The Plots pane accepts legacy metrics and vectors plus versioned forge_plot: JSON. Structured plots and their order, series visibility, and log settings persist across launches (bounded to 128 plots and 16 MiB). Reorder history, duplicate a plot into an independently configurable copy, transform axes to log10, and toggle individual series. Export the whole collection or one plot as JSON, standalone SVG, native 960×540 PNG or vector PDF, or self-contained interactive HTML with series toggles, hover coordinates, wheel zoom, and drag pan — with no network resources.

Embedded training

Forge embeds Burn 0.22 with training, metrics, the portable Flex CPU backend, and WGPU. The Deep pane runs a native tensor self-test or Run native Burn training, which trains an autodiff linear layer with SGD on a CPU/Flex or WGPU backend.

Hyperparameters
epochs 1–10,000 and lr above 0 through 1; validated and recorded in the run label.
Validation & early stopping
validation reserves a deterministic tail holdout (0–50%) reported as the epoch MSE; patience stops after N validation epochs without improvement (0 disables it).
Train on your data
Enable use selected dataset and name distinct feature/target columns — up to 100,000 finite pairs, standardized with training-partition statistics only, with loss reported in original units.

A completed run produces a schema-2 native regression artifact with the fitted original-unit equation, preprocessing statistics, score, exact data fingerprint, backend, and optimizer configuration. Predict a single value inline, or choose Predict selected dataset to score a whole table into a new Arrow-backed <source>_predictions dataset with MAE / RMSE / R², actual-vs-predicted, and residual plots.

Training runs on a background worker, streams backend-labeled progress into Millwright Studio, and can be cancelled without a false completion. WGPU needs a compatible local adapter; CUDA/ROCm are available for generated projects and remote jobs but rejected for embedded training.

Registry & deployment

With a project open, Register native model stores the active artifact as immutable bytes with SHA-256 metadata. Load registry version resolves a version or promoted alias, verifies registry integrity, and validates the schema before replacing the active model.

Promote an alias and Generate Rust service to produce a standalone Axum service for that immutable version. Its POST /predict accepts up to 10,000 finite values and ships with integrity-checked startup, readiness, metadata, health probes, and Docker / Compose / Kubernetes files.

The Deploy pane ingests forge_service: and forge_drift: events, showing request volume, error rate, p95 latency, and explainable feature-drift breaches — with native plots, offline HTML/PDF reports, and attested, integrity-verified monitoring bundles.

SQL workbench

The SQL pane runs one read-only analytical statement at a time over embedded SQLite plus the official DuckDB, PostgreSQL, and MySQL clients. It permits SELECT, WITH, EXPLAIN, SHOW, DESCRIBE, and VALUES forms and rejects stacked or mutating statements before dispatch. Passwords go only in Forge's password field, are stored in the OS credential manager, and never touch project JSON or command arguments. External commands stop after 30 seconds; previews are bounded to 10,000 rows and 64 MiB. Successful statements are recorded in a project-scoped, deduplicated history you can recall, export, or clear.

Object storage

The Storage pane connects to S3-compatible buckets and configured rclone remotes without storing their credentials. Test reachability, browse bounded listings, and download objects into a per-profile local cache under .forge/object-cache/ with atomic, size-limited, redacted transfers. Operations run on the same background integration worker as database calls, so the editor keeps painting while a request is in flight.

Remote Jupyter

Remote profiles accept HTTPS Jupyter or JupyterHub base URLs (plain HTTP only for localhost). Tokens live in the OS credential manager and are passed to bounded requests without persistence. Test the server's kernelspecs, start one managed kernel, and run code — or route Run Cell / Run Above / Run All through the remote kernel over an authenticated TLS WebSocket. Results and rich MIME payloads (HTML, Markdown, SVG, PNG, JSON) return to the originating cell and are shown as inert source rather than executed. Input requests open a focused, masked dialog; Cancel and Interrupt use a separate control lane so they stay responsive even while execution is blocked.

Accessibility

Settings offer light/dark themes, a 10–24 px editor font, high contrast, reduced motion, and caret blinking. Reduced motion disables the custom blinking caret. Execution, diagnostics, Git state, and cells use text or symbols in addition to color, so status never depends on color alone. The whole workspace is keyboard-reachable via the command palette, Ctrl+1–9, and F6.

Privacy & updates

Diagnostics are off by default. Settings can enable bounded local events and sanitized crash summaries for the open project; Forge never uploads them automatically. Use the explicit ZIP export to review the exact bundle before sharing. External tools (Cargo, Git, gh, Jupyter, Python, AWS CLI, rclone, DuckDB, PostgreSQL, MySQL) own their own credentials — Forge project JSON contains only profile metadata and opaque credential keys, never tokens or passwords.

Use Crates → Check signed updates to download the channel manifest, verify its GitHub provenance attestation, and report the matching platform artifact. Forge never installs or replaces the executable automatically.
