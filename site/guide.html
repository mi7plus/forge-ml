Guide

Using Forge ML

Forge ML is a desktop scientific IDE for Rust machine-learning projects. Open a Cargo project, edit Rust scripts or //# %% notebooks, and run cells in a persistent Evcxr console. This guide covers the workspace end to end.

Install & run

Forge ML is a Cargo workspace. On Windows, use a Visual Studio Native Tools command prompt so Cargo can find the MSVC linker:

cargo run

Release installers bundle the correct rust-analyzer for each platform. Development builds can install or repair it from the Help pane, or manually:

rustup component add rust-analyzer
Tagged releases build an NSIS installer for Windows, a DMG for macOS, and DEB/AppImage packages for Linux, each with the matching rust-analyzer sidecar and a build-provenance attestation. Forge can report an available update, but installing it is always an explicit action.

The workspace

The layout follows the scientific-IDE model: an editor in the center surrounded by tool panes.

Left — navigation

Project and Outline tabs. The outline links functions, structs, enums, traits, impls, and modules; project-wide search gives clickable line/column results.

Right — inspectors

Variables, Data, Plots, Runs, Search, Help, Problems, Git, Crates, GitHub, Studio, SQL, Deep, Deploy, and Storage — one pane at a time (docking is on the roadmap).

Bottom — console

The interactive Rust console with persistent Evcxr state and command history, plus a Python tab.

Center — editor

Multiple tabs with independent unsaved-change protection, inline rust-analyzer diagnostics, and a caret-anchored completion popup.

Notebook cells

Separate cells with a //# %% <name> marker. Cells share one Evcxr session, so setup and dataset cells define values that later cells use.

//# %% setup
let learning_rate = 0.05_f64;
let epochs = 8_usize;

//# %% data
let features = vec![1.0_f64, 2.0, 3.0, 4.0, 5.0];
let targets  = vec![2.2_f64, 4.1, 6.0, 8.2, 10.1];

//# %% train
let mut weight = 0.0_f64;
for _ in 0..epochs {
    let g = features.iter().zip(&targets)
        .map(|(x, y)| (weight * x - y) * x).sum::<f64>() / features.len() as f64;
    weight -= learning_rate * g;
}
println!("Learned weight: {weight:.4}");

Publish visualizations from any cell via stdout:

println!("forge_metric:loss={}", loss);          // live line chart
println!("forge_vector:weights=0.2,0.7,1.1,1.8"); // bar plot
println!(r#"forge_table:samples={"columns":["x","label"],"rows":[[0.2,"cat"]]}"#);
Structured forge_plot: JSON supports 11 plot families — lines, scatter, bars, areas, histograms, box summaries, heatmaps, ROC, precision–recall, residuals, and feature importance — with per-series toggles, log axes, and SVG/PNG/PDF/interactive-HTML export.

Data & experiments

Import CSV, TSV, JSON Lines, Parquet, or Arrow IPC from the Data pane or the Tools menu. Parsing runs in the background and opens the result in the lower-right viewer only after Arrow construction and quality profiling finish. Interactive imports are bounded (512 MiB on disk, 1M rows, 10k columns); query or stream larger sources.

Each dataset gets a cached quality profile — missingness, numeric coverage, uniqueness, range, mean, standard deviation, mixed-type and constant-column alerts, and bounded Pearson correlations. The data grid is virtualized, so wide tables stay responsive while you filter, sort, pin/hide columns, edit drafts, and build linked scatter plots from a selection.

Runs carry SHA-256 provenance over dataset contents, source identities, the Cargo lockfile, and runtime metadata. Name, snapshot, compare, clone, archive, and export runs as ZIP bundles; produce EDA and experiment-comparison reports as offline HTML or native PDF.

Embedded training

Forge embeds Burn 0.22 with training, metrics, the portable Flex CPU backend, and WGPU. The Deep Learning pane runs a native tensor self-test or Run native Burn training, which trains an autodiff linear layer with SGD on a CPU/Flex or WGPU backend.

  • Set epochs (1–10,000) and lr (>0 through 1); values are validated and recorded in the run label.
  • validation reserves a deterministic tail holdout (0–50%) and reports its MSE per epoch.
  • patience stops after N validation epochs without improvement (0 disables early stopping).
  • Enable use selected dataset and name distinct feature/target columns to train on workspace data — up to 100,000 finite pairs, standardized with training-partition statistics only, loss reported in original units.

A completed run produces a schema-2 native regression artifact with the fitted equation, preprocessing statistics, score, exact data fingerprint, backend, and optimizer configuration. Predict a single value inline, or choose Predict selected dataset to score a whole table into a new Arrow-backed <source>_predictions dataset with MAE/RMSE/R², actual-vs-predicted, and residual plots.

Training runs on a background worker, streams backend-labeled progress into Millwright Studio, and can be cancelled without emitting a false completion. WGPU needs a compatible local adapter; CUDA/ROCm are available for generated projects and remote jobs but rejected for embedded training.

Registry & deployment

With a project open, Register native model stores the active artifact as immutable bytes with SHA-256 metadata. Load registry version resolves a version or promoted alias, verifies registry integrity, and validates the schema before replacing the active model.

In Model Registry & Deployment, promote an alias and Generate Rust service to produce a standalone Axum service for that immutable version. Its POST /predict accepts up to 10,000 finite values and ships with integrity-checked startup, readiness, metadata, health probes, and Docker/Compose/Kubernetes files.

The deployment pane ingests framework-neutral forge_service: and forge_drift: events, showing request volume, error rate, p95 latency, and explainable feature-drift breaches — with native plots, offline HTML/PDF reports, and attested, integrity-verified monitoring bundles.

SQL & object storage

The SQL workbench runs one read-only analytical statement at a time over embedded SQLite plus the official DuckDB, PostgreSQL, and MySQL clients. It permits SELECT, WITH, EXPLAIN, SHOW, DESCRIBE, and VALUES forms and rejects stacked or mutating statements before dispatch. Passwords go only in Forge's password field, are stored in the OS credential manager, and never touch project JSON or command arguments.

The Storage inspector connects to S3-compatible buckets and rclone remotes without storing their credentials. Test reachability, browse bounded listings, and download objects into a per-profile local cache with atomic, size-limited, redacted transfers.

Database, storage, import, and export work all runs on a background integration worker, so the editor keeps painting and accepting input while a request is in flight.

Accessibility

Settings offer light/dark themes, a 10–24 px editor font, high contrast, reduced motion, and caret blinking. Reduced motion disables the custom blinking caret. Execution, diagnostics, Git state, and cells use text or symbols in addition to color, so status never depends on color alone.

Privacy

Diagnostics are off by default. Settings can enable bounded local events and sanitized crash summaries for the open project; Forge never uploads them automatically. Use the explicit ZIP export to review the exact bundle before sharing. External tools (Cargo, Git, gh, Jupyter, Python, AWS CLI, rclone, DuckDB, PostgreSQL, MySQL) own their own credentials — Forge project JSON contains only profile metadata and opaque credential keys, never tokens or passwords.
